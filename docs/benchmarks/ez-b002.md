# EZ-B002 — Geographic Nuclear-Chart Holdout

Protocol version: `1.0.0`. No legacy alias.

EZ-B001 asks whether the models could predict later *historical* knowledge.
EZ-B002 asks whether they can reconstruct a region of the *known* chart when
every truth value inside that region is withheld. It is the first direct
rehearsal for prediction into unknown territory.

```text
b002-select-regions -> deterministic candidate windows -> preregistered regions.json
b002-prepare        -> identity-only targets inside one region + split manifest
b002-freeze         -> KnowledgeFreeze over the eligible nuclei outside the region
b002-predict        -> fit + certificates, one sealed run per model
b002-finalize       -> LEDGER_FINALIZED
b002-score          -> unlock region truth, only after finalization
```

Experiment-level wrappers: `b002-seal-experiment` then `b002-score-experiment`.

## Region types

```text
rectangle   z_min <= Z <= z_max  and  n_min <= N <= n_max
isotopic    Z fixed,             n_min <= N <= n_max
isotonic    N fixed,             z_min <= Z <= z_max
```

Bounds are inclusive. All three are stored in one normalized rectangle form, so
an isotopic segment is a rectangle with `z_min == z_max`. The first production
benchmark uses rectangles. Schema: `schemas/geographic_region.schema.json`.

## Split

```text
targets  = all eligible nuclei inside the region
training = all eligible nuclei outside the region
```

Target masses enter no fit, no feature, no hyperparameter, and no uncertainty
calibration. Target identities (Z, N, A) are allowed. Schema:
`schemas/geographic_split_manifest.schema.json`.

One frozen snapshot per benchmark version; editions are never combined.

## Why blindness is enforced differently than in EZ-B001

EZ-B001 forbids a *file*: the later edition is a different table with a
different hash, so blindness can be checked at the filesystem boundary. A
geographic holdout has no second file — training and truth live in the same
snapshot — so the boundary is geometric and is enforced in code on every fit:

- only rows whose identity is in `training_nuclide_ids` are loaded,
- the loaded corpus must reproduce `training_identity_digest` exactly,
- no loaded row may be inside the region,
- no target may appear in the fitted identity list,
- the fitted model manifest is scanned for the withheld identities,
- scoring asserts the truth table *is* the frozen snapshot, rather than
  asserting it is a different one.

## Freeze and split digest

One KnowledgeFreeze per region x model-suite data split. The split digest
(`ez-b002-split-digest-v1`) binds five things:

```text
raw_source_hash
region_manifest_hash
training_identity_digest
target_identity_digest
feature_policy_hash
```

`freeze_id` is content-addressed from that digest, so a region swap, a snapshot
swap, or one extra training identity invalidates every certificate quoting the
old freeze. The region manifest hash also enters the ModelFitFact.

## Extrapolation depth

```text
nearest_training_L1 = min over training nuclei of abs(Z_t - Z_r) + abs(N_t - N_r)
```

This is the primary extrapolation-depth coordinate. Metrics are reported by
exact depth, by distance bucket, by Z band, by region, and by model, and the
worst region per model is named rather than absorbed into a pooled average.

## No accuracy pass/fail in v1

EZ-B002 v1 is characterization. Engineering PASS means correct masking, absent
leakage, scored and calibrated outputs, and reproducible results. No
"successful extrapolator" threshold is defined, and none may be added after
seeing the results; a scientific threshold requires a later preregistered
protocol version.

STOP if regions are changed after seeing performance, if only easy regions are
retained, if target values enter normalization statistics, or if hyperparameters
are tuned against hidden-region truth.

## Committed experiment

`experiments/EZ-B002-v1/` runs the protocol on a committed **synthetic** nuclear
chart (`tests/fixtures/b002/synthetic_chart_v1.mas20`), because the evaluated AME
tables are licensed upstream files that stay gitignored. Its numbers are software
evidence for the protocol, not scientific evidence about nuclei. See
`experiments/EZ-B002-v1/PREREGISTRATION.md` for the AME2020 path, which is a new
experiment id rather than an edit of this one.
