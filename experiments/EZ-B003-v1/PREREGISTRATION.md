## 0. The boundary, before anything else

```text
EZ-B003 measures ONE narrow capability: rediscovery of KNOWN shell-related mass
structure under controlled masking.

A met criterion is NOT proof that a new magic number exists.
A met criterion is NOT evidence that a predicted Z = 154 shell gap exists.
A met criterion is NOT evidence for an island of stability anywhere.
```

That later claim would require independent physics-model ensembles, deformation
calculations, fission calculations, decay competition, and far larger
extrapolation uncertainty. Describing successful mass interpolation as proof of a
new island of stability is a **stop condition** of this benchmark, not a result.

The statement is not carried by this file alone. It travels inside every artifact
as `boundary_rule`, and every criterion verdict carries `scope_rule` beside it.

## 1. Research question

EZ-B001 asks whether the frozen model suite could predict later *historical*
knowledge. EZ-B002 asks whether it can reconstruct a *region* of the known chart
when every truth value inside it is withheld. EZ-B003 asks the harder question:

    after the neighborhood of a known shell closure is withheld,
    does the reconstructed mass surface still show the shell-gap structure
    that is actually there?

## 2. Scope of this experiment: synthetic mechanics only

```text
scored scope                   synthetic
evaluated mass table verdict   NOT_YET_SCORED
thresholds                     FROZEN
```

**No closure of an evaluated mass table has been scored under this criterion.**
The thresholds in section 8 were calibrated on the synthetic benchmark mechanics
only, frozen, and written to `CRITERION.json` by the *seal* phase before any
withheld closure truth was read. Scoring a real AME closure is a separate, later
act, under a new experiment id, and it may not change a threshold.

`real_closure_status` in `shell_aggregate.json` records this state explicitly, so
a reader of the numbers cannot mistake a synthetic mechanics result for a
statement about the evaluated chart.

## 3. Data snapshot

One frozen snapshot, one edition, no edition mixing.

| Role | Edition parser | File | sha256 |
| --- | --- | --- | --- |
| snapshot (training and truth) | AME2020 | `tests/fixtures/b003/synthetic_shell_chart_v1.mas20` | `2d5226f315b43664f78e86ee1dd050d353490aa525e9fa9784598aba2c514938` |

The committed snapshot is a **synthetic nuclear chart with an injected shell-like
discontinuity**, not an evaluated mass table. It is generated by
`tests/helpers.py::write_synthetic_shell_chart`: the EZ-B002 toy binding surface
plus a deterministic smooth non-SEMF ripple, plus two injected kinks in the
binding energy

```text
E_shell(Z, N) = -g_n * max(0, N - N0) - g_p * max(0, Z - Z0)

N0 = 50, g_n = 1.5 MeV      Z0 = 28, g_p = 1.2 MeV
```

It is written in AME2020 mass-table format and read by the ordinary AME2020
parser, so the whole benchmark runs through production code paths.

Why this shape. A ReLU kink is exactly what a shell closure leaves in a mass
surface: the two-nucleon separation energy drops by a constant once the closure is
passed. Expanding the indicator shows the injected feature is a spike of known
height at exactly one coordinate and zero everywhere else in the same parity
class:

```text
delta2n(Z, N0)   = 2*E(N0) - E(N0-2) - E(N0+2) = +2*g_n
delta2n(Z, N0+2) = 2*E(N0+2) - E(N0) - E(N0+4) =  0
delta2n(Z, N0-2) = 2*E(N0-2) - E(N0-4) - E(N0) =  0
```

The neutron kink depends only on N and the proton kink only on Z, so `delta2n`
sees only `g_n` and `delta2p` only `g_p`. The chart is a rectangle
(Z 24-44, N 38-58) rather than a valley band on purpose: every chain then holds
the whole search window, so the mask can hide *every* occurrence of the injected
closure instead of leaving edge chains that still carry it.

The synthetic chart exists because the evaluated AME tables are licensed upstream
files that stay gitignored (`data/raw/`). A committed synthetic snapshot makes
EZ-B003 v1 reproducible from a clean checkout with no external download.

    The numbers in this experiment are software evidence, not scientific
    evidence. They demonstrate that the hidden-shell protocol masks, derives,
    ranks, seals, scores, and reproduces correctly. They say nothing about
    nuclear physics.

Only `ground_truth_eligible == True` rows are used, under
`ez-gt-policy-v1:evaluated_non_estimated_only`. 420 of the snapshot's 441 rows
are eligible.

## 4. Two profiles, never pooled

| profile | features | may be quoted as |
| --- | --- | --- |
| `discovery` | `Z`, `N`, `A` | a rediscovery result |
| `accuracy` | may later add physics-informed shell features | an accuracy result only |

This experiment runs the `discovery` profile:
`ez-b003-discovery-identity-zn-v1`, feature policy hash
`14baf7be41ac2244e3a746acdec32347bcdf64f5737792eec139212d1d68e9ab`.

Forbidden: distances to known magic numbers, `is_magic` flags, named shell
closures, shell-gap lookup tables, and target truth.

`ez-b003-discovery-feature-firewall-v1` is a code-level denylist over normalized
feature names covering `magic`, `shell_distance`,
`distance_to_20/28/50/82/126`, `known_closure`, and `shell_label`, including
their case, hyphen, and camelCase variants. It is re-run against the *fitted*
model's declared features, not only against the declared policy.

The denylist is defense in depth. The primary protection is this explicit
feature-policy manifest, whose hash enters the split digest. Pooling a discovery
result with an accuracy result is a protocol error: a model told where the shells
are has not rediscovered them.

## 5. Mask geometry

Half-width one (`schemas/shell_mask.schema.json`):

```text
neutron closure N0:   N in {N0-1, N0, N0+1},  z_min <= Z <= z_max
proton  closure Z0:   Z in {Z0-1, Z0, Z0+1},  n_min <= N <= n_max
```

Half-width one is the smallest mask that keeps the indicator at the closure a
prediction rather than a lookup, because `delta2n(Z,N0)` expands to
`2*B(Z,N0) - B(Z,N0-2) - B(Z,N0+2)`: the closure mass is withheld while its two
two-step neighbors stay in training. Hiding one single point would leave `N0-1`
and `N0+1` in training, and interpolating two immediate neighbors is not
reconstructing shell structure.

The span on the orthogonal axis is the contiguous hull of every chain holding an
eligible nucleus inside the neighborhood — **not** the hull of the supported
chains. A shell gap at `N0` lives on the closure coordinate and is identical
along every chain, so one unmasked chain still carrying its own `N0`
neighborhood would hand the model the answer for all the others. Support decides
which chains are *scored*; the neighborhood is hidden wherever it exists.

## 6. Availability rule and support rule

The availability set is declared, not chosen (`shell_masks`):

```text
neutron   N = 20, 28, 50, 82, 126
proton    Z = 20, 28, 50, 82
```

Which members are *produced* is decided by the support rule alone, never by how
well a model does on them. `ez-b003-support-rule-v1`, computed from identities
only:

```text
chain is supported when
    it holds at least one eligible masked target
    the indicator at the closure itself is computable
    the two-step lower neighbor (closure - 2) is eligible and outside the mask
    the two-step upper neighbor (closure + 2) is eligible and outside the mask
    it holds >= MIN_CHAIN_LENGTH eligible nuclei outside the mask in the window
    >= MIN_PEAK_CANDIDATES window positions have a computable indicator

closure is EVALUABLE when
    >= MIN_EVALUABLE_CHAINS chains are supported
    and the mask holds >= MIN_TARGETS eligible targets
```

Frozen settings, written before any scoring:

```text
half_width            = 1
MIN_CHAIN_LENGTH      = 5
MIN_TARGETS           = 6
MIN_EVALUABLE_CHAINS  = 3
MIN_PEAK_CANDIDATES   = 3
PEAK_WINDOW           = 6
```

A closure that fails the rule is reported `NOT_EVALUABLE` **with its reasons**.
It is never silently omitted, because a benchmark that quietly drops the closures
it cannot handle reports only the closures it can.

## 7. Split, freeze, and leakage rule

For each evaluable closure:

```text
targets  = all eligible nuclei inside the closure neighborhood
training = all eligible nuclei outside it
```

No target mass may enter fitting, feature construction, hyperparameter tuning, or
uncertainty calibration. Target identities (Z, N, A) are allowed. As in EZ-B002,
there is no second file to forbid — training and truth live in one snapshot — so
blindness is enforced in code on every fit: only `training_nuclide_ids` rows are
loaded, the loaded corpus must reproduce `training_identity_digest`, no loaded row
may be inside the mask, no target may appear in the fitted identity list, and the
fitted model manifest is scanned for the withheld identities.

One KnowledgeFreeze per closure x model-suite data split. The split digest
(`ez-b003-split-digest-v1`) binds six things:

```text
raw_source_hash
challenge_manifest_hash
mask_hash
training_identity_digest
target_identity_digest
feature_policy_hash
```

`freeze_id` is content-addressed from that digest, so a mask swap, a snapshot
swap, a profile relabel, or one extra training identity produces a different
freeze and invalidates every certificate quoting the old one.

## 8. Derived observables and the frozen criterion

```text
B(Z,N)       from predicted mass excess, via binding_energy_MeV
S2n(Z,N)     = B(Z,N) - B(Z,N-2)
S2p(Z,N)     = B(Z,N) - B(Z-2,N)
delta2n(Z,N) = S2n(Z,N) - S2n(Z,N+2) = 2*B(Z,N) - B(Z,N-2) - B(Z,N+2)
delta2p(Z,N) = S2p(Z,N) - S2p(Z+2,N) = 2*B(Z,N) - B(Z-2,N) - B(Z+2,N)
```

No model trains on a derived target binding energy. Every derived value is
recorded as `derived = true`, `independent_evidence = false`, with its exact
input identities and the origin of each input, because a shell gap re-expresses
the masses it was built from. The predicted indicator is a hybrid fixed by the
mask geometry before any hidden truth is read
(`ez-b003-hybrid-derivation-v1`): the sealed prediction at every masked input,
the frozen training mass at every unmasked one.

Per closure and chain: `true_<indicator>`, `predicted_<indicator>`,
`absolute_<indicator>_error`, `sign_recovered`, and `local_peak_rank` as
`rank_1` / `top_3` / `outside_top_3`. Candidates in the search window share the
**parity** of the closure, because the two-nucleon difference only cancels the
pairing term within one parity class; a mixed-parity ranking would compare a
pairing artifact with a shell gap.

No p-value is reported for peak localization: no null model is preregistered in
v1. A large positive local `delta` can indicate shell structure. Not every local
maximum is a magic number.

### `ez-b003-rediscovery-criterion-v1`

All four conditions, over the supported chains, plus a per-closure report:

```text
sign_recovered_fraction   >= 0.75
top_3_fraction            >= 0.75
rank_1_fraction           >= 0.50
abs(coverage_90 - 0.90)   <= 0.15
```

The calibration term is there so a model cannot satisfy the shell criterion with
uncertainties that are not honest.

These thresholds were calibrated on the synthetic benchmark *mechanics* — that
the mask hides the neighborhood, that the indicators derive, and that a correct
reconstruction ranks the injected feature first — and **not** by looking at any
model's shell results. They are frozen. `CRITERION.json` is written and hashed by
the seal phase; the score phase re-derives the digest and refuses to run if it
moved. Changing a threshold requires a new B003 protocol version and a complete
rerun with the old result preserved.

    A threshold selected after real scoring is a stop condition, not a result.

## 10. Atlas hypotheses

Two competing structures per masked closure, plus the masking itself recorded as
a `BOUNDARY_CHANGE` intervention:

```text
H0 = no local shell discontinuity at the closure
H1 = a local shell discontinuity at the closure
```

`ez-b003-hypothesis-decision-v1`: a chain supports H1 when the indicator at the
withheld closure is positive and ranks first in the window, and H0 when the
indicator is not positive. A hypothesis becomes `SELECTED_REPRESENTATIVE` for a
surface only on a strict majority of that closure's evaluable chains. Two
resolutions are recorded: one from snapshot truth, which restates what the chart
contains, and one from the sealed reconstruction, which is the benchmark
question.

The pair is created at seal time, before any truth is read, and rebuilt at score
time from the same inputs; a mismatch in the content-addressed identities is a
protocol error. This is evidence bookkeeping. Unrelated Atlas conjectures are not
imported.

## 11. Order of operations

```text
select challenges  ->  commit challenges.json
                   ->  seal every evaluable closure + freeze CRITERION.json
                   ->  commit the seal
                   ->  score
```

`SEALED_PREDICTIONS.json` is written with state
`PREDICTIONS_SEALED_CLOSURE_TRUTH_UNREAD` and hashed into
`SEALED_PREDICTIONS_SHA256` before any truth inside a closure neighborhood is
read. `CRITERION.json` lands in the same phase, for the same reason. Scoring
refuses a run whose finalization marker changed after the seal.

## 12. Stop conditions

STOP if a known closure label reaches a discovery-model feature, if target truth
is used to tune hyperparameters, if a threshold is selected after real scoring,
if successful mass interpolation is described as proof of a new island of
stability, if masks are changed after seeing performance, if a `NOT_EVALUABLE`
closure is silently omitted, or if a sealed run is refit.

## 13. Atlas evidence
