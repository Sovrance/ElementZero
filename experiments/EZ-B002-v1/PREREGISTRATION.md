# Preregistration — EZ-B002-v1

Benchmark: EZ-B002 — Geographic Nuclear-Chart Holdout
B002 protocol version: 1.0.0
Evidence protocol version: 0.3.0
Region manifest hash: `9b7d97fdbd617eb550415c385cc42d8f11af7179bba29d431712cbaa471a5976`

This document is prose. Every load-bearing value lives in `regions.json`
(covered by `REGIONS_SHA256`) and in the sealed run artifacts. Editing this file
cannot change a region, a hash, or a policy.

## 1. Research question

EZ-B001 asks whether the frozen model suite could predict *later historical*
knowledge. EZ-B002 asks a different question:

    can the suite reconstruct a region of the known chart
    when every truth value inside that region is withheld?

This is the first direct rehearsal for prediction into unknown territory.

## 2. No accuracy pass/fail

EZ-B002 v1 is characterization. Engineering PASS means:

- masking is correct,
- leakage is absent,
- outputs are calibrated and scored,
- results reproduce.

No "successful extrapolator" threshold is defined, and none may be added after
seeing these numbers. A scientific threshold requires a later preregistered
protocol version.

## 3. Data snapshot

One frozen snapshot, one edition, no edition mixing.

| Role | Edition parser | File | sha256 |
| --- | --- | --- | --- |
| snapshot (training and truth) | AME2020 | `tests/fixtures/b002/synthetic_chart_v1.mas20` | `94cff436bf38c6b0acec35d96f6d35cd4c7dfa71959b97dc4347648abaa4a75a` |

The committed snapshot is a **synthetic nuclear chart**, not an evaluated mass
table. It is generated by `tests/helpers.py::write_synthetic_chart`: a smooth
drifting valley of stability carrying a semi-empirical binding surface plus a
deterministic, smooth, non-SEMF ripple. It is written in AME2020 mass-table
format and read by the ordinary AME2020 parser, so the whole benchmark runs
through production code paths.

It exists because the evaluated AME tables are licensed upstream files that stay
gitignored (`data/raw/`). A committed synthetic snapshot makes EZ-B002 v1
reproducible from a clean checkout with no external download.

    The numbers in this experiment are software evidence, not scientific
    evidence. They demonstrate that the geographic-holdout protocol masks,
    seals, scores, and reproduces correctly. They say nothing about nuclear
    physics.

Only `ground_truth_eligible == True` rows are used, under
`ez-gt-policy-v1:evaluated_non_estimated_only`. 427 of the snapshot's rows are
eligible.

### Running the same protocol on AME2020

The protocol is snapshot-agnostic. With the real table present at
`data/raw/amdc/AME2020/mass_1.mas20.txt`, the identical three stages are:

```bash
elementzero benchmark b002-select-regions \
    --source data/raw/amdc/AME2020/mass_1.mas20.txt --edition AME2020 \
    --output experiments/EZ-B002-AME2020/regions.json \
    --candidates-output experiments/EZ-B002-AME2020/region_candidates.json
elementzero benchmark b002-seal-experiment \
    --source data/raw/amdc/AME2020/mass_1.mas20.txt --edition AME2020 \
    --regions experiments/EZ-B002-AME2020/regions.json \
    --dir experiments/EZ-B002-AME2020
elementzero benchmark b002-score-experiment \
    --source data/raw/amdc/AME2020/mass_1.mas20.txt --edition AME2020 \
    --dir experiments/EZ-B002-AME2020
```

That is a **new experiment id**, never an edit of this one. The eligible point
set differs, so the deterministic candidate order differs, so the selected
regions differ. Reusing `EZ-B002-v1` for a second snapshot would make one
experiment id mean two different region sets.

## 4. Region types

Supported region objects (`schemas/geographic_region.schema.json`):

```text
rectangle   z_min <= Z <= z_max  and  n_min <= N <= n_max
isotopic    Z fixed,             n_min <= N <= n_max
isotonic    N fixed,             z_min <= Z <= z_max
```

Bounds are inclusive on both axes. EZ-B002 v1 uses rectangles.

## 5. Region-generation policy

Regions are generated, not hand-picked. The generator is deterministic and its
order depends only on the snapshot — never on a metric, an error, or a model.

```text
candidate_policy_id  = ez-b002-rectangle-window-candidates-v1
selection_policy_id  = ez-b002-z-band-selection-v1
z_span               = 4
n_span               = 5
min_targets          = 8
min_supported_sides  = 2
regions_per_band     = 1
z_bands              = light (Z 0-20), medium (Z 20-50), heavy (Z 50-82)
candidate_order      = (Z band index, -n_targets, region_id)
```

1. every eligible nucleus anchors one `z_span x n_span` window,
2. windows with fewer than `min_targets` eligible nuclei are dropped,
3. windows with training support on fewer than `min_supported_sides` of their
   four faces are dropped,
4. survivors are sorted by `candidate_order`,
5. the first `regions_per_band` of each Z band are selected.

411 candidates survived filtering. The full candidate list is committed in
`region_candidates.json` so a reader can verify that the selected regions are
the deterministic top of the order and not a retained-because-easy subset.

## 7. Split and leakage rule

For each region:

```text
targets  = all eligible nuclei inside the region
training = all eligible nuclei outside the region
```

No target mass may enter fitting, feature construction, hyperparameter tuning,
or uncertainty calibration. Target identities (Z, N, A) are allowed.

EZ-B001 enforces blindness at the filesystem boundary, because the later edition
is a different file with a different hash. A geographic holdout has no second
file: training and truth live in the same snapshot and the boundary is
geometric. So blindness is enforced in code, on every fit:

- only rows whose identity is in `training_nuclide_ids` are loaded,
- the loaded corpus must reproduce `training_identity_digest` exactly,
- no loaded row may be inside the region,
- no target may appear in the fitted identity list,
- the fitted model manifest is scanned for the withheld identities.

The target manifest exposed to prediction contains exactly `A, N, Z,
nuclide_id`, validated on load.

## 8. Freeze structure

One KnowledgeFreeze per region x model-suite data split. The split digest binds
five things (`ez-b002-split-digest-v1`):

```text
raw_source_hash
region_manifest_hash
training_identity_digest
target_identity_digest
feature_policy_hash
```

`freeze_id` is content-addressed from that digest, so a region swap, a snapshot
swap, or one extra training identity produces a different freeze and invalidates
every certificate quoting the old one.

Feature policy: `ez-b002-identity-zn-v1` — features are Z, N, A. Forbidden:
region-derived features, shell/magic-number distances, and any statistic
computed from inside the withheld region.

## 9. Distance to boundary

For each held-out target:

```text
nearest_training_L1 = min over training nuclei of abs(Z_t - Z_r) + abs(N_t - N_r)
```

This is the primary extrapolation-depth coordinate. Errors and calibration are
reported by depth (`ez-b002-exact-l1-depth-v1`).

## 10. Model suite

The exact three frozen EZ-B001 models, unchanged:

| model_id | implementation | random_state |
| --- | --- | --- |
| EZ-SEMF-LS-v1 | `src/elementzero/models/gp_residual.py::SEMFLeastSquaresModel` | 0 |
| EZ-GP-DIRECT-v1 | `src/elementzero/models/gp_residual.py::GPDirectModel` | 0 |
| EZ-SEMF-GP-RESIDUAL-v1 | `src/elementzero/models/gp_residual.py::SEMFGPResidualModel` | 0 |

No weak baseline is removed; a weak model is reported, which is what makes a
strong extrapolation claim checkable. Additional mass models require a versioned
B002 protocol.

Every model of a region sees the same freeze, the same targets, and the same
snapshot, which is asserted rather than assumed.

## 11. Metrics

Primary: `MAE_keV`, `MedAE_keV`, `RMSE_keV`, `NLPD`, `coverage_90`,
`coverage_95`, `calibration_error_90`, `calibration_error_95`.

Diagnostics: metrics by `nearest_training_L1`, by region, by model, worst-region
error per model, and calibration versus depth.

Every selected region is reported for every model. A missing region/model pair
is a protocol error, which is what stops a run from quietly reporting only the
regions that reconstructed well.

## 12. Order of operations

```text
select regions  ->  commit regions.json  ->  seal every region
                ->  commit the seal      ->  score
```

`SEALED_PREDICTIONS.json` is written with state
`PREDICTIONS_SEALED_REGION_TRUTH_UNREAD` and hashed into
`SEALED_PREDICTIONS_SHA256` before any truth inside a region is read. Scoring
refuses a run whose finalization marker changed after the seal.

## 13. Stop conditions

STOP if regions are changed after seeing performance, if only easy regions are
retained, if target values enter normalization statistics, if hyperparameters
are tuned against hidden-region truth, or if a sealed run is refit.

## 14. Atlas evidence

The EZ-B001 graph, with the geographic split inside the freeze node:

```text
artifact -> training dataset -> knowledge freeze (+ geographic split)
         -> model fit (+ region_id, region_manifest_hash)
```
